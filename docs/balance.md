# Баланс CyberHack

## Методика

Баланс проверяется ботами-симуляторами. Они играют через публичный API движка (`getLegalActions` / `applyAction`).

| Файл | Что делает |
|---|---|
| `packages/engine/tools/bots.ts` | Два бота: `novice` и `expert` |
| `packages/engine/tools/simulate.ts` | Прогон N забегов по `worker_threads`, отчёт в консоль и JSON в `tools/out/` |
| `packages/engine/tools/debug-run.ts` | Один забег по сиду: итог, хвост действий, колода |

Запуск:

```bash
npm run sim -- --runs 10000 --bot expert --class all --ascension 0 --seed-prefix sim
# в PowerShell npm съедает `--`, поэтому так:
cd packages/engine; npx tsx tools/simulate.ts --runs 10000 --bot expert
```

Параметры: `--runs N`, `--bot novice|expert`, `--class all|netrunner|phreaker|ghost`, `--ascension K`, `--seed-prefix P` и `--threads T` (по умолчанию все ядра, максимум 16). Сид забега строится как `${prefix}-${class}-${i}`, классы чередуются. Поэтому прогон полностью детерминирован: один и тот же сид всегда даёт тот же результат, а на разных ядрах результат одинаковый.

### Боты

**Новичок.** Если суммарный урон из намерений врагов больше текущего блока, играет карту с самым большим блоком. Иначе играет самую сильную атаку по врагу с наименьшим HP, а когда атак нет — прочие карты. На экране награды пропускает карту с вероятностью 30%, в остальных случаях берёт случайную. Узел на карте выбирает случайно. На отдыхе лечится, если HP < 50%, иначе улучшает случайную карту. В магазине покупает случайный товар, пока хватает золота. В событиях выбирает случайный вариант.

**Опытный.**
- **Тир-лист карт** считается из эффектов, а не задаётся вручную, поэтому он сам обновляется при правках JSON. Ценность эффектов делится на (стоимость + 0.6). Синергии: Вирус у Фрикера, Разгон у Нетраннера, Шифрование и добор у Призрака (×1.4). Отдельно учитывается нужда колоды в AoE и блоке.
- **Колода держится компактной.** Порог взятия карты растёт с размером колоды. В магазине бот сначала удаляет стартовые Пинг/Файрвол и проклятия, но оставляет минимум блока. Потом покупает лучшее по соотношению ценность/цена.
- **Путь по карте** выбирается динамикой по всем путям до босса. Элиты бот берёт, когда колода сильная и HP > 60%. Отдых ценнее при HP < 55%, магазин — при золоте ≥ 140.
- **Бой.** Бот перебирает последовательности розыгрыша руки: DFS с таблицей транспозиций, лимит 260 узлов, одинаковые карты не дублируются. Каждый лист оценивается настоящей симуляцией конца хода и хода врагов на копии состояния через `playCard`/`endTurn` движка. Поэтому Брешь, Лаг, Разгон, Вирус, Контрудар и блок учитываются точно. В оценку листа входят:
  - потерянное HP, причём вес растёт при низком HP;
  - урон по врагам, взвешенный по их входящему урону;
  - большой бонус за убийство, сильнее для опасных врагов;
  - остаток Вируса и дебаффов на врагах;
  - постоянные баффы игрока.
- **Карты добора** завершают ветку с бонусом за ожидаемую ценность добранных карт. После розыгрыша бот перепланирует ход, то есть порядок колоды он не подсматривает.
- **Страховка:** не больше 60 розыгрышей за ход.

### Метрики

- Винрейт по классам, средний и медианный этаж смерти, смерти по актам, топ-10 энкаунтеров-убийц. Для убийц считается и доля смертей среди тех, кто с ними сражался.
- Для обычных боёв акта 1 — процент смертей, когда бой состоялся.
- **Pick rate карты** = взяли / предложили. Учитываются награды и витрина магазина.
- **Win rate delta** рассчитана так, чтобы не было survivorship bias. F — медианный этаж, на котором карту (или реликвию) получали. Сравниваются забеги, которые к этажу F получили предмет, с забегами, которые прошли этаж F без него. Забеги, умершие ровно на этаже F без предмета, исключаются: иначе проигравшие боссу попадали бы в группу «без», и награда за босса выглядела бы сверхсильной. Значение показывается только при n ≥ 20 в обеих группах.

## Найденные баги

1. **Бесконечное комбо «Скан портов+».** Улучшенная версия стоила 0, добирала 2 карты и не сжигалась. Три копии плюс «Затенение» давали бесконечный цикл добора и блока: у бота за ход набиралось 9964 блока. Из-за этого Призрак выигрывал до 90% забегов, а один забег завис. Исправлено в контенте. Добавлен регрессионный тест в `content.test.ts`: у карты с нулевой стоимостью без сжигания не может быть добора ≥ 2 и нет прироста энергии с добором. Там же новый тест «реальный контент валиден». Раньше проверялось только то, что JSON загружается.
2. **Дебаффы игрока тают раньше атак врагов** (не исправлено, контент не затрагивает). Длительность Бреши, Лага и Фрагментации на игроке уменьшается в конце его хода, до ходов врагов. Брешь 1, наложенная на игрока, не сработает ни разу, а намерение при этом покажет урон с ×1.5. Сейчас враги накладывают Брешь только по 2-3, так что на игру это не влияет. Если появятся дебаффы длительностью 1, тик для игрока нужно перенести на конец раунда.

## Известные перекосы

- **Классы у новичка разъезжаются**: Фрикер 11%, Призрак 2.6%. Призрак требует точного розыгрыша бесплатных карт, а случайный бот этого не умеет. У опытного классы ровные.
- **Почти никогда не берутся опытным** (pick < 1% в v2): n_miner, ph_ransomware, ph_backup, n_hotfix, n_admin_key, nr_thermo_shield, gh_flurry, nr_flood_loop.
  - Нейтральные карты бывают только в магазине.
  - Ransomware и Backup после нерфа (win rate delta была > +15) бот оценивает ниже порога.
  - Отчасти это свойство формулы бота: она сильно ценит карты за 0.
- **Реликвии.** В v2 максимум +14.6 п.п. (r_shuriken_script, r_smart_watch). Для реликвий жёсткой цели нет.
- В `docs/content.md` остались старые HP классов и боссов и старые описания стартовых реликвий. Актуальные числа — в JSON.
