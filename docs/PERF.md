# Производительность: замеры и решения

## Как мерить

```bash
npm run build -w @cyberhack/web
cd apps/web && npx vite preview --port 4173      # в отдельном терминале
node e2e/tools/perf-probe.mjs 4 desktop          # троттлинг CPU 4x, 1440x900
node e2e/tools/perf-probe.mjs 4 desktop lite     # то же в режиме «экономия графики»
node e2e/tools/perf-probe.mjs 4 mobile           # 360x780, DPR 2
```

`perf-probe.mjs` проходит меню → выбор класса → карту (прокрутка) → вход в бой → наведение на карты руки → два хода → окно настроек и для каждой сцены печатает: FPS по rAF, p95 длительности кадра, кадры дольше 50 мс, long tasks (число и максимум), число и время layout/style, время JS.

`perf-profile.mjs` снимает CPU-профиль входа в бой и одного хода и печатает топ функций по self-time. Для читаемых имён нужна сборка без минификации:
`npx vite build --minify false --outDir <dir>`, затем `npx vite preview --outDir <dir> --port 4174`, затем `node e2e/tools/perf-profile.mjs 4174`.

Окружение: Windows 10, Edge (Playwright, channel msedge), Radeon 680M (ANGLE D3D11, GPU настоящий, не SwiftShader), `reducedMotion: no-preference`.
**Шум:** замеры снимались, пока ещё два Claude параллельно собирали и тестировали проект, поэтому FPS одной и той же сцены гуляет на ±30%. Надёжны большие разрывы (13 → 59 FPS) и детерминированные метрики (профиль CPU, размер DOM); мелкие различия — нет.

## Что нашлось

| # | Причина | Где | Вклад |
|---|---------|-----|-------|
| 1 | Вечные CSS-анимации внутри SVG юнитов и карт (`art-*`, `ea-*`, `art-spin` в картах руки) поверх `filter: drop-shadow` — SVG заново растеризуется с фильтром каждый кадр | polish.css, enemies-zones.css, combat.css | Бой в простое: все анимации на паузе → 145 FPS, со всеми → 40–80 FPS (4x) |
| 2 | Полноэкранные фоны анимируют `background-position` (небо `sky-far`/`sky-near`, частицы `motes`, сетка пола с `mask` + `drop-shadow` + 3D) — перерисовка всего слоя каждый кадр | polish.css, combat.css | Меню на десктопе 18–32 FPS, бой 11–22 FPS |
| 3 | Рука: 5 карт = 766 из 1078 узлов DOM боя (~150 SVG-узлов на арт карты), у каждой `drop-shadow` + вложенный `drop-shadow` на `.art-hero` | CardArt.tsx, polish.css | Наведение на карты: 20–25 FPS |
| 4 | Компиляция шейдеров Pixi и загрузка текстур на первом эффекте в бою (`getProgramParameter`, `texImage2D`) | fx/fx.ts | ~25 мс JS в первом ходу (4x) → 0 |
| 5 | Вход в бой — long task 650–800 мс (4x): JS ~200 мс, пересчёт стилей ~270 мс, layout ~200 мс. Первый принудительный layout (~145 мс) приходится на `FitText` в Card.tsx, но он лишь первым читает геометрию: layout всё равно случился бы перед кадром (проверено: бинарный поиск и кэш в FitText время не меняют) | разметка боя целиком | не исправлено, см. «Осталось» |
| 5a | Причина двойного layout при входе в бой: `handW` стартовал с 600, карты рендерились под неверную ширину, после замера вся рука перерисовывалась (карты меняли размер → container queries → FitText) и кадр делал второй полный layout на 60–90 мс | screens/CombatScreen.tsx | **исправлено** |
| 5b | Pixi вешает `pointermove` на весь `document` и на каждое движение мыши вызывает `getBoundingClientRect` (`mapPositionToPoint`) — принудительный layout; `EventsTicker` делает hit-test каждый кадр. Канвасы эффектов не интерактивны | fx/fx.ts, fx/rain.ts | **исправлено** |
| 6 | Обучение: rAF-цикл с `getBoundingClientRect` и `querySelector` каждый кадр, пока активен шаг | tutorial/Tutorial.tsx | только во время обучения; не мой файл → handoff |

Проверено и в порядке: подписки zustand в бою — через селекторы; `setInterval`/`addEventListener` в CombatScreen и MetaBits чистятся; `backdrop-filter` в проекте не используется; звук (`audio/sfx.ts`) создаёт узлы на звук и не держит их; утечек слушателей нет.

## Что сделано

- **Режим «Экономия графики»** (`fx/perf-mode.ts`, правила в `styles/perf.css`, атрибут `<html data-gfx="lite|full">`):
  - `auto` (по умолчанию) включает экономию при `prefers-reduced-motion`, на слабом устройстве (`deviceMemory ≤ 2`, `hardwareConcurrency ≤ 2`, `saveData`) или если в первом бою медиана кадра хуже ~30 FPS (замер 3 с через 1,5 с после входа, результат запоминается на устройстве);
  - экономия гасит вечные декоративные анимации фонов, юнитов и артов карт, `drop-shadow`/`mix-blend-mode`/маски, большие размытые тени; не запускает Pixi-дождь (минус один полноэкранный WebGL-канвас); в эффектах боя рисует каждую третью частицу и цифры урона без размытой тени;
  - переключатель `fx/PerfToggle.tsx` (Авто / Экономия / Полная) — нужно подключить в окне настроек, см. handoff;
  - вид по умолчанию на нормальном устройстве не меняется.
- **Прогрев Pixi** (`fx/fx.ts`): шейдеры частиц, текстуры и шрифт чисел урона готовятся в `requestIdleCallback` после старта, а не на первом ударе.
- **Ширина руки до первого замера** (`screens/CombatScreen.tsx`): берётся из сохранённого замера для текущего размера окна, без него — оценка по раскладке. `ResizeObserver` и первый замер читают одну величину (`clientWidth`), поэтому совпавшее значение не вызывает второй рендер. Второй полный layout при входе в бой исчез.
- **События Pixi отключены** в обоих канвасах (`eventMode: 'none'`, `eventFeatures` выкл., `setTargetElement(null)`): движение мыши больше не форсирует layout.
- Инструменты замеров: `e2e/tools/perf-probe.mjs`, `e2e/tools/perf-profile.mjs`.

Проверено и отброшено:
- `will-change: transform` на `.hand-card__inner` даёт при наведении лишь +5 FPS (p95 49 → 35–42 мс) и рискует оставить увеличенную карту размытой — не внесено.
- Стабильный полный relayout экрана боя стоит 3 мс (4x): вёрстка сама по себе не тяжёлая, дорог только первый показ новых узлов.
- Подмена шрифтов на системный и фиксированный размер текста карт дают около 10% первого layout — не причина.

## Осталось

1. **Long task при входе в бой (~500 мс на 4x, было 650–800)**: React ~220 мс + первый layout ~110 мс + стили ~70 мс. Дальше нужна переделка вне моих файлов, чтобы узлов было меньше: облегчить `CardArt` (≈150 SVG-узлов на карту → один `<use>`/спрайт или растровая картинка из кэша), убрать вложенный `drop-shadow` на `.art-hero`, проверить стоимость container queries (`cqw`) у карт. Подробности — в `docs/handoff/feat-perf.md`.
2. Вид по умолчанию на интегрированной графике остаётся тяжёлым (бой 15–22 FPS на 4x). Его защищает авто-замер FPS в первом бою, который переключает в экономию. Облегчать сам вид по умолчанию без изменения внешнего вида дальше нельзя: анимации внутри SVG не выносятся на композитор.
3. Повторить замеры на свободной машине: ДО/ПОСЛЕ для полной графики сейчас в пределах шума.
